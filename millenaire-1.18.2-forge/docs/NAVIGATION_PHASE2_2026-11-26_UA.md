# Навігація: етап 2, перша перевірена збірка — 26.11.2026

База: `9c0ece1`, гілка `fix/villager-door-access-and-village-territory`.
Версія лишається `8.1.2-port.0`. Main не змінено. Зміни локальні, без push/merge.

## Підтверджені причини та виправлення

1. **JPS reconstruction:** parent chain має порядок goal→start, але вибір висоти ґрунту спрямований. Старий backTrace заново обирав проміжні Y від кінця; на багаторівневій колонці це дає інший поверх. Тепер макроребро розгортається від батьківського вузла в напрямку пошуку, кінцева висота звіряється з jump point. При невідповідності повертається відмова з наявним classic fallback. Валідація кожного ребра та deadline збережені. Сліпої інтерполяції Y немає. Старий JPS sentinel Y=0 не перероблено в цьому пакеті.
2. **Follower:** ванільний followThePath може пропускати вузол за скалярним добутком без перевірки нового зрізаного ребра; airborne branch також пропускає вузли нижче сутності. На реальному ванільному класі тест відтворює shortcut, а на PathNavigateSimple — збереження вузла. Для AS_PathEntity тепер потрібне фізичне досягнення центру та висоти опори; зберігаються повороти перед сходами/дверима. Висота нижньої плити враховується через WalkNodeEvaluator.getFloorLevel. Досягнення rung контролює лише ladder assist, включно з одиночною драбиною без вертикальної частини маршруту. Таймаути/recovery не вимкнені.
3. **Драбина:** зсув центру на 0.12 до стіни при ширині NPC 0.6 перетинає реальний 3/16 collision panel усіх чотирьох орієнтацій драбини. Це доведено VoxelShape-тестом. Новий центр клітинки вільний. VillagerMoveControl не додає ground-jump/горизонтальне прискорення, коли ladder assist уже керує рухом; обнуляє застарілу JUMPING operation. Перший rung вище NPC без контакту лишає звичайний підхід/стрибок. Це усуває конкретні конфлікти керування, але ще не доводить проходження всіх драбин у грі.
4. **Неприпустимий підйом:** clearance більше не приймає +2 по Y як звичайний крок, навіть якщо піднята AABB порожня. Спуск -2 лишається лише за allowDropping. Консервативний cache admission може не зберігати такі двоблокові спуски; це безпечний miss, не зміна руху.
5. **Двері біля (22,66,571):** збереження `Новий світ (1)` прочитано без змін. У fixture сходи facing=north, а двері (22,67,570) facing=east, hinge=right, open=true. Відчинена панель фізично перекриває вхід уздовж Z. Старий clearance повністю ігнорував дерев'яні двері. Тепер DoorPassageGeometry вибирає стан панелі за напрямком конкретного ребра, а A* перевіряє її справжню форму. Серверний менеджер використовує ту саму політику: звичайні двері відчиняє, поперечно поставлені за потреби зачиняє, щоб звільнити прохід. Перед таким зачиненням перевіряє майбутню панель на живих істот. Player override, powered-door захист і спільне закривання після проходу збережені. Самі споруди/напрямки дверей у збереженні автоматично не перебудовуються.

## Реальні перевірки

- Повна Forge `build`: **BUILD SUCCESSFUL**; це компіляція/пакування, Gradle test має NO-SOURCE.
- `tools/validate_production.py`: **175 Python checks**, п'ять Java smoke-програм, production audit 7 культур / 285 профілів / 499 goals; ERROR немає, 239 REVIEW не оголошуються дефектами автоматично.
- 11 Java NAV-OPT smoke-програм: PASS (cache, executor, snapshot reuse/mutation, backoff, drift). PowerShell-обгортка після них не знайшла Python через `py`; Python suite окремо виконано явним шляхом до Python 3.
- LadderTransitionRulesSmoke та TransitionClearanceRulesSmoke: PASS.
- `tools/check_navigation_geometry.py`: **32 виконувані assertions** на скомпільованих класах мода та справжніх Forge/Minecraft 1.18.2 класах. Перевіряє follower і vanilla baseline, низьку стелю, заборону +2, нижню плиту, ladder shapes чотирьох орієнтацій, власника руху, JPS reconstruction, геометрію входу й виходу hotspot, вибір стану дверей серверним менеджером.
- Fixture `tools/fixtures/navigation-stair-22-66-571.json` містить знімок 8×9×8 блоків із наявного збереження, не повний світ. Невідомі модові блоки в цьому тесті трактуються як суцільні; сам перевірений коридор використовує vanilla stairs/door/walls. Відповідність геометрії на момент старого логу не гарантується, але координати/стан сходів збігаються.

Запуск геометричного тесту: після `build-local.ps1 -Tasks build,writeMigrationClasspath` виконати `python tools/check_navigation_geometry.py` з кореня Forge-проєкту. Потрібен реальний Python 3. Тест не запускає Minecraft і не читає/змінює світ.

## Що ще не підтверджено

Ігрового проходження поточним JAR, контрольованих TPS/CPU/GC вимірів і server multiplayer acceptance ще немає. Етап 2 **не закрито**.

Перший playtest: вхід (22,66,571) в обох напрямках; драбини (212,74,679), (190,66,677), (3,67,561), (26,61–67,655); декілька NPC у дверях, ручне перемикання дверей, переривання цілі. Спостерігати фактичне проходження, а не тільки ASTAR-RESULT. Зафіксувати JAR hash та новий лог.

Залишаються: повний фізичний контракт для fractional stairs/low ceiling/jump/drop та всіх stair shapes; partial blocks/chests; native fallback і конфлікти зустрічних проходів; actual ladder top-out/descending; стрибки при високих тестових швидкостях. Семплювання clearance ще консервативне, не точний симулятор траєкторії. Не прибирати teleport recovery до підтвердження гри. Оптимізації NAV-OPT snapshots/cache/executor збережені; новий фоновий доступ до живого світу не додано.
