# Village book and resource icons — 24.11.2026

The 28-minute playtest reports a NullPointerException in LanguageUtilities.string at line 327, called by PanelContentGenerator.generateSummary at line 1025. buildingGoalIssue is legitimately null while a goal is queued without an active construction or known obstruction. Both summary and resource views now omit absent status text. The two string overloads accept null/blank keys; an unresolved project plan is displayed by key without dereferencing it. A missing plan set in the active construction list also falls back to its key.

The quarry tooltip previously read ResManager.sourceTypes on the client, but the building packet only serialized chests, furnaces, firepits, signs, stalls, banners and culture banners. The sourceTypes array is a server-side array parallel to source coordinates, so we do not populate it on the client. Instead the packet now includes a bounded list of registered block state IDs (max 1024) and the client exposes a separate immutable displaySourceTypes list. The existing GoalMinerMineResource tooltip uses that list, retaining its exact output mapping (sand, sandstone, cobblestone, clay, gravel, etc.). The source block is not necessarily the output block. No production behavior or world data is changed. No source coordinates sent.

Network protocol changed from 1.18.2-2 to 1.18.2-3; client and dedicated server must be updated together. Singleplayer integrated server uses the same jar. Save format unchanged. The packet read and write order is symmetric, before optional marvel data. Does not prove a particular food-oriented Mayan village has a sandstone source. External culture definitions and actual settlement data are required for that determination.
